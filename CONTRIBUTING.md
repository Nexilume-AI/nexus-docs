# Contributing

**English** · [Chinese](CONTRIBUTING_zh.md)

Keep Chinese and English Markdown paths paired. Start tutorials with prerequisites, runnable steps and expected results; distinguish examples from production defaults. Document actual implemented behavior and the version tested.

Keep English prose in English files. Put Chinese explanations in separate `_zh.md`
files or the Chinese documentation trees, with reciprocal language links.
`npm run check:language` validates English Markdown and visible translation messages;
Chinese i18n lookup keys and localized page components remain supported.
`npm run build` also checks every generated English page and search index, including
navigation, breadcrumbs and accessible labels. Only the native language name in
the language selector is exempt. After a build, rerun this check with
`npm run check:language:build`. Autogenerated sidebar categories need matching
English keys in the plugin's `current.json`; translated `_category_.json` files
alone do not prevent fallback labels.

Run `npm run check:docs`, `npm run check:security` and `npm run build` before submitting a pull request. Update the lockfile deliberately when dependencies change. API documentation is generated from the SDK, not edited to make a stale check pass.

Only commit authored documentation, approved illustration sources and text examples. Exclude `.env`, keys, credentials, personal data, logs, build output, caches and SDK checkouts. Use synthetic screenshots and review all visible text. Contributions must be yours to license under the repository license; preserve third-party notices.

Report bugs with page URL, expected behavior and redacted reproduction steps. Do not send private documents or account details.
